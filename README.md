# toon_generator

개인 작업용 로컬 플랫폼에서 인스타툰 프로젝트를 설정하고, 에피소드의 콘티와 이미지 초안을 만드는 AI 보조 파이프라인을 정의한다.

> **캐릭터 대화와 ChatGPT 구독 연결 — 2026-10-18:** D-0036/D-0037에 따라 특징 입력 → 필요한 질문 → 방향 카드 → 수정 → 정확 버전 확인을 LangGraph·SQLite에 연결했다. 기본 캐릭터 제공자는 앱 자체의 **Sign in with ChatGPT** 연결이다. 로그인·구독 사용 동의·모델 선택 후 사용하며, 한도 도달 시 멈춘다. 유료 API 자동 전환은 없다. 캐릭터 시각 후보·실제 시트·이미지 생성은 아직 구현하지 않았다.

새 화면은 [구독 연결 안내](docs/chatgpt-subscription-guide.md), [캐릭터 대화 안내](docs/character-direction-guide.md), [구현 검증 기록](docs/studio-implementation-validation.md)을 참고한다. 이전 이야기 기술 테스트는 `?storyFixture=1`, Stage 01–05 프로토타입은 `?legacy=1`에서 확인한다. 실제 캐릭터 시트가 없는 새 프로젝트는 이야기 제작을 시작할 수 없다. 연결 성공 여부와 실제 대화 검증은 별도로 기록한다.

## 실행

2026-10-12의 명시적 구현 요청(D-0027)에 따라 `platform_build`로 전환해 로컬 MVP를 구현했다. 현재 기본 화면은 D-0037의 ChatGPT 구독 연결을 사용하는 캐릭터 대화다. 이전 제작 흐름과 규칙 기반 MOCK 이미지는 별도 기술 검증 경로에 보존한다.

- 이 PC에서는 `Toon Studio.lnk` 또는 `Start-ToonStudio.cmd`를 실행하면 앱과 브라우저가 열린다.
- 접속 주소: `http://127.0.0.1:8765`.
- 처음 설치하거나 화면을 다시 빌드할 때는 `scripts/Install-ToonStudio.ps1`을 실행한다. 평소 실행에는 Node.js나 터미널 명령이 필요하지 않다.
- 사용 방법, 설치·저장 위치와 검증 명령은 [로컬 플랫폼 사용 안내](docs/local-platform-guide.md)에 기록한다.

## 프로젝트 목표

첫 번째 검증 목표는 실제 에피소드 제작이 아니라 플랫폼이다. Stage 01–05의 프로젝트 설정부터 콘티와 이미지 초안 검토까지를 합성 데이터와 모의 이미지 생성기로 검증한 뒤, 별도 승인된 경우에만 실제 프로젝트를 시작한다. 프로젝트별 주인공과 시리즈 설정은 재사용하고, 에피소드의 캐릭터 일관성과 소유 경계를 유지한다.

현재 제작 사이클의 결과물은 사람 검토를 위한 콘티와 초안이다. 콘티 그림은 기본적으로 1단계 비트 썸네일 수준으로 간단히 두되, 컷별 글에는 G2 검토와 Stage 05 이미지 생성에 필요한 행동·상태·구도·텍스트 책임·연속성 정보를 적는다. 모호하거나 복잡한 컷만 추가로 구체화한다. 이미지 초안은 컷별 파일과 한 편 전체 배치 미리보기를 제공한다. 사용자는 대사·컷 설명을 수정하고, 컷별 이미지 후보를 선택하거나 필요한 컷만 재생성한다. 직접 그리기·픽셀 보정·자르기·말풍선 배치용 이미지 편집기는 첫 범위에 포함하지 않는다. 게시 가능한 최종본, 리터칭, QA·권리 검수는 이 첫 사이클의 완료 기준에 포함하지 않는다.

AI는 조사·초안·생성·국소 수정·체크리스트 작성을 보조할 수 있지만, 캐릭터 방향, 권리 판단, 최종 품질, 게시를 대신 승인하지 않는다.

## 기존 프로토타입 범위

- 현재 MVP 범위: 개인 1명이 자신의 컴퓨터에서 사용하는 로컬 플랫폼, Stage 01–05 흐름, 합성 데이터, 외부 호출 없는 모의 이미지 생성
- 화면: 사용자 PC에서 브라우저로 열고 해당 PC의 loopback 연결만 허용하는 로컬 웹 UI
- 다른 PC에서 플랫폼 접속: 로컬 MVP 범위에서 제외하고 후속 단계로 미룸 (D-0015)
- 프로젝트 정보와 이미지 파일: MVP에서는 사용자 PC에 저장하고, 설정·자료·이미지·버전·검토 기록을 포함한 전체 프로젝트 백업 내보내기를 지원 (D-0016, D-0017)
- 백업마다 일반 파일 또는 age 암호화를 선택하고 저장 위치를 고른다. 암호화할 때 긴 암호문구 생성과 강도 안내를 제공하며 복구에도 같은 암호문구가 필요하다. 분실한 암호의 복구는 불가 (D-0021–D-0024)
- 로컬 자료는 PC 계정 접근으로 보호하며 앱 암호는 생략한다. 레퍼런스는 사용자 선택 파일을 프로젝트에 복사하고 원본은 유지한다. 자동 버전 정리와 프로젝트 전체 삭제는 MVP 범위 밖이다 (D-0022, D-0025, D-0026).
- 복구는 새 `project_id`를 가진 별도 복사본으로 생성하고 원본 프로젝트·백업 ID를 출처로 보존한다. 설정·자료·이미지·버전·검토·작업 기록과 체크섬을 확인한 뒤 등록하며, 복사한 검토 기록은 역사로 보관하고 현재 승인은 다시 받는다 (D-0018, D-0019, D-0028).
- 클라우드 동기화는 후속으로 미룸
- 이미지 공급자 검증: 이후 단계에서 합성 프롬프트/자산만 사용하며, 공급자·인증정보·전송조건·비용·실패/재시도 조건의 명세와 별도 승인이 선행됨
- 실제 제작: 플랫폼 수락 검토가 끝난 뒤에도 별도 명시적 사용자 전환이 있어야 시작
- 형식: 1컷·다컷 등으로 고정하지 않고 에피소드 요청과 허용된 레퍼런스의 구조적 관찰에 따라 선택
- 후속 범위: Stage 06 리터칭·QA·게시 준비, Stage 07 고도 자동화, Stage 09 기술 글·포트폴리오
- 보류: 호스팅형 멀티유저 운영, 다중 계정 예약·권한, 자동 게시, 운영용 LoRA 학습, 경쟁 계정 자동 수집

## 기존 로컬 MVP의 프로젝트 모델

로컬 플랫폼은 제작 프로젝트를 서로 격리한다. 각 제작 프로젝트는 다음과 같은 프로젝트 브리프를 별도로 가진다. 프로젝트는 주인공과 시리즈 설정을 재사용하는 경계이며, `content_id` 하나는 인스타툰 에피소드 한 편을 가리킨다.

- 계정/콘텐츠 주제
- 주 캐릭터
- 주요 시청자
- 원하는 분위기
- 사용할 수 있는 형식과 편집 제약
- 피하고 싶은 요소

레퍼런스, 캐릭터 바이블, 시리즈 전략, 콘텐츠 아이템, 생성·검수 기록은 기본적으로 하나의 `project_id`에 귀속된다. 다른 프로젝트의 설정이나 자산을 자동으로 섞지 않으며, 공유가 필요할 때는 별도의 공유·복제 결정과 provenance를 남긴다. MVP 검증에서는 합성 프로젝트 자료만 사용한다.

## 콘텐츠 흐름

```text
프로젝트 설정(01–03, 재사용)
  -> 에피소드 요청/레퍼런스
  -> 스토리 제안 또는 제공된 스토리 정리
  -> 콘티(G2 사람 승인)
  -> 컷별 이미지 + 전체 배치 초안(G3 사람 검토)
```

기존 합성 프로토타입은 짧은 소재에서 규칙 기반 이야기 방향을 제안하고 사람이 선택·수정한다. 실제 창작 AI를 호출한 결과는 아니다. 구체적인 스토리나 대사가 이미 있으면 요청한 범위 안에서 보존해 콘티로 옮긴다. 요청과 레퍼런스가 형식을 분명히 가리키지 않거나 서로 충돌하면 초안을 만들기 전에 선택을 확인한다. 레퍼런스는 구성·리듬 등 추상적 관찰에만 사용하며 보호되는 캐릭터·문구·패널·특징적인 그림을 복제하지 않는다.

Stage 06 이후에는 기존 확장 흐름인 `human_retouch -> ai_refine (optional) -> qa -> approved -> published`가 이어진다. `ai_refine`의 상태 전이 방식은 별도 후속 명세 정합화 항목이다. `approved`와 실제 게시 상태는 구분하고, 사람 승인 없이 자동으로 진행하지 않는다.
