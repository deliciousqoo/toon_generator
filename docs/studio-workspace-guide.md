# 작업 공간 사용 안내

2026-10-18부터 기본 진입은 **캐릭터 대화**다. [캐릭터 대화 안내](character-direction-guide.md)를 먼저 참고한다. 아래 내용은 `?storyFixture=1`에서 유지하는 이전 Stage 04 합성 기술 테스트의 안내이며, 새 프로젝트의 캐릭터 기반을 대체하지 않는다.

현재는 **합성 테스트 전용**이다. 가상의 입력으로 역할별 처리와 수정·검토·복구를 확인한다. 실제 계정, 캐릭터, 레퍼런스, 개인 경험과 작품 자료는 입력하지 않는다. 실제 사용 흐름에 필요한 독립 캐릭터 창작과 시각 콘티 생성은 아직 구현하지 않았다.

## 설치와 실행

1. 저장소의 `toon_generator` 폴더에서 `scripts/Install-ToonStudio.ps1 -RebuildFrontend`를 실행한다. 설치는 Python 의존성 확인과 화면 빌드를 수행한다. 기존 앱이 실행 중이면 `Stop-ToonStudio.cmd`로 종료한 뒤 설치한다.
2. `Toon Studio.lnk` 또는 `Start-ToonStudio.cmd`로 실행한다. 기본 주소는 `http://127.0.0.1:8765`이다. 설치 후 평소 실행에는 별도 빌드가 필요하지 않다.
3. 앱은 현재 PC의 loopback에서 실행한다. 코드와 잠금된 의존성은 Git으로 다른 PC에서 설치할 수 있으며 GPU 기준을 현재 PC에 고정하지 않는다. 다른 PC에서 동일한 작업 데이터를 옮기는 v2 전체 백업은 후속 통합 대상이다.

## 한 화면에서 진행하기

1. **프로젝트:** 이름, 독자·대상, 잠정 시리즈 방향을 입력한다. 합성 테스트 확인은 지금 실행 범위를 표시한다. 캐릭터·톤·에피소드 제목·컷 수를 앞서 입력하지 않는다.
2. **이야기 재료:** 아이디어, 경험·썰, 정리된 이야기, 이야기 참고 자료 중 용도를 고르고 가상의 내용을 적는다. 현재 프로젝트 소유의 합성 캐릭터/시리즈 정확 버전을 기반으로 실행한다. 이 fixture가 실제 캐릭터 단계 완료를 의미하지 않는다.
3. **이야기 확인:** 초안과 검토 의견을 읽고 수정하거나 컷 구성을 제안받는다. 기본 worker는 결정론적 예시이므로 자연어 창작 능력을 제공했다고 표시하지 않는다. `대사:` 또는 `행동:` 피드백은 정해진 필드를 바꾸며 나머지 내용은 보존한다. 일반 의견은 이력으로 남지만 창작 수정 결과로 해석하지 않는다.
4. **컷 구성:** 선택한 이야기에 근거한 형식 제안을 확인한다. 현재 기술 fixture는 비트당 한 컷을 제안한다. 컷 합치기/나누기와 풍부한 대안은 후속 창작 planner 평가·구현 항목이다.
5. **콘티 구조:** 컷별 행동·표정·구도·시선·호흡·연결·대사 데이터를 읽는다. 현재는 텍스트 fixture이며 실제 시각 러프가 없다. 특정 컷의 대사·행동을 수정하거나 **이야기부터 수정**하여 서사를 다시 검토할 수 있다.
6. **기술 흐름 확인:** 최종 버튼은 합성 처리 흐름만 확인한다. 실제 G2 승인, 이미지 생성 준비, 창작 품질 수락을 만들지 않는다. 완료 이후에도 수정이 가능하며 새 버전은 다시 확인한다.

현재 단계와 작업 요약이 자동 갱신된다. 수정하면 영향을 받은 작업만 다시 실행하고, 이전 결과·독립 평가·사람 확인 기록을 보존한다. 버전 기록에서 이전 내용을 읽을 수 있다. 화면이 오래된 요청을 보내면 충돌을 알려주고 최신 결과를 불러온다.

## 중단·재시도·복구

- 작업 멈추기는 결과를 삭제하지 않는다. 실행 중 모델 요청은 반환된 뒤 이후 역할을 실행하지 않는다.
- 실행 실패/중단에는 명시적 재시도가 필요하다. 자동 일시 오류 재시도는 역할 호출당 1회, 자동 창작 재작성은 구간당 최대 2회다. 한도가 소진되면 마지막 결과와 필요한 선택을 남긴다.
- 반려/중단 뒤 재시도는 같은 작업 범위를 다시 실행한다. 새로운 방향을 적용하려면 수정 요청으로 의견을 보내거나 새 테스트 이야기를 시작한다.
- 앱을 종료·재실행하고 새로고침하면 SQLite 체크포인트로 현재 사람 확인 지점과 작업을 복구한다. 확인 완료 결과의 수정은 새 체크포인트에서 시작하며 이전 체크포인트도 보존한다.
- 기본 데이터는 `%LOCALAPPDATA%\ToonStudio` 아래에 저장한다. 새 작업의 projection/이벤트/버전/호출 예산은 `studio/studio.sqlite3`, 그래프 상태는 `studio/checkpoints.sqlite3`에 있다. 기존 v1 프로젝트는 별도 데이터다.
- 기존 백업 메뉴는 v1 전용이다. 새 studio 작업을 포함한 완전한 백업·복원 기능은 아직 제공하지 않는다.

## 선택적 모델 연결

Ollama `/api/generate` JSON 어댑터 코드와 역할별 story/planner/evaluator 지시는 구현했다. 실제 제공자 호출·모델 품질·속도는 아직 검증하지 않았다. 기본 모드는 모델을 호출하지 않고 외부 추적도 비활성화한다.

모델 실행은 P1에서 정확 모델·라이선스·실제 실행 위치·입력·시간·횟수를 정한 뒤에 연결한다. loopback 주소만으로 서버의 실제 추론 위치를 보증하지 않으므로 클라우드 위임 여부도 확인해야 한다. 현재 어댑터는 선별된 합성 Stage 04 텍스트만 허용하는 경로다. 모델을 UI에서 임의로 선택하거나 원본 자료를 자동 업로드하지 않는다.

운영자 연결 시 `TOON_STUDIO_ENABLE_OLLAMA=1`, `TOON_STUDIO_OLLAMA_MODEL`, `TOON_STUDIO_PROVIDER_APPROVAL_FILE`을 사용한다. 승인 파일은 명시적인 실행 허가, 동일 모델, `ollama_local_json`, `synthetic_stage04`, 고정 loopback 주소, 호출/timeout 상한을 요구한다. [설정 예시](contracts/studio-provider-approval.example.json)의 `execution_authorized:false`는 실행을 허용하지 않는다. 숫자는 예시이며 모델 실행 전 확인해야 한다. 자격 증명과 실제 승인 파일은 Git에 저장하지 않는다.

이야기 생성·콘티 계획·각 독립 평가는 서로 다른 지시와 정확 입력 버전을 받는다. 평가기의 수정 추천에는 근거·위치·수정 의견이 있어야 하고, 사람이 확인할 결과는 평가기가 승인하지 않는다. 이미지 생성, ComfyUI/ControlNet/IP-Adapter/Krita 연결은 후속 작업이다.
