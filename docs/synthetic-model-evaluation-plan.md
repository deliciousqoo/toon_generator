# 합성 모델·이미지 흐름 비교 계획

## 1. 목적·권한·입출력

이 문서는 목표 PC의 로컬 이미지 경로와 외부 후보를 같은 합성 입력으로 비교하기 위한 **명세와 시험 계획**이다. 현재 `specification_only`이며 D-0029의 구현 보류가 유지된다. 실제 캐릭터·에피소드 자료 수집, 합성 fixture 작성/이미지 생성, 코드 구현, 모델 설치, 제공자/API 호출을 수행하지 않는다. 시험 실행은 범위·자료전송·비용 조건을 확인한 별도 명시적 승인 후의 작업이다. 시험 승인도 실제 콘텐츠 실행이나 공개 권한을 부여하지 않는다.

- 미래 입력: 사람이 검토한 합성 character/reference, story, storyboard, 한국어 text/layout 패키지의 고정 버전; 시험 rubric; 후보 명세; 목표 PC 프로필; 별도 실행 승인 기록.
- 미래 출력: 후보별 시도/실패 기록, run manifest, 컷별 결과와 전체 미리보기, 차원별 평가, 비용/전송/보관 기록, 사람의 선택·거절·보류 기록.
- 소비자: Stage 05의 후보 선택 및 실행 preflight. 결과는 사람 G3 승인이나 Stage 06·출판 승인을 대신하지 않는다.

합성 시험 입력과 미래 실제 콘텐츠 입력은 분리한다. 사용자의 캐릭터, 일화, 대사, 파일, 외부 레퍼런스를 합성 시험에 넣지 않는다. 여기서는 구체 캐릭터·장면을 채우지 않고 `unknown`/예시 ID만 사용한다.

## 2. 목표 PC와 이동성

현 PC의 GPU는 기준으로 삼지 않는다(D-0033). `target_machine_id`, OS, GPU/VRAM, RAM, 드라이버/runtime, 여유 저장 공간, 설치 권한과 경로는 모두 **미정**이다. 높은 사양이 필요한 경우 다른 PC에서 평가할 수 있다. 목표 PC를 선택한 다음, 선택한 로컬 모델·노드·플러그인·도구 버전의 공식 요구사항과 라이선스를 해당 프로필에 대조한다. 제품명만으로 VRAM이나 속도를 단정하지 않는다.

목표 PC 또는 실행 승인이 없으면 로컬 측정은 `not_run`으로 남긴다. 외부 결과만 얻었다면 부분 관찰이며, 로컬 대비 우열·완료된 비교로 보고하지 않는다. D-0031의 로컬 우선 선호는 유지하되, 하드웨어/품질/속도와 자료전송 조건이 맞을 때 사용할 외부 경로는 실측과 사람 선택으로 판단한다.

소스·명세·비밀이 아닌 설정 예시·의존성 잠금 정보·설치 절차는 Git으로 이동 가능하게 계획한다. 기기 절대 경로는 로컬 설정으로 분리한다. 키·모델 가중치/캐시·프로젝트 DB·레퍼런스·생성 미디어는 Git 밖에 둔다. PC 간 자료 이동, 백업, 복구, 무결성 확인과 삭제 정책은 별도 선택 사항이다. 다른 목표 PC로 옮기면 동일 버전 설치/실행 복원 여부를 다시 평가하고, 미시험 상태를 재현 성공으로 쓰지 않는다.

## 3. 후보와 현재 미결 값

| 후보 | 역할과 질문 | 실행 전 확인할 사항 |
|---|---|---|
| Gemini 외부 경로 | 선택한 참조로 캐릭터 정체성과 컷 의도를 유지하는가? | 실제 사용 가능한 모델 ID/revision, endpoint/tier, 참조/편집 지원, 출력 조건, 가격, 데이터 사용·보관 약관 |
| OpenAI 외부 경로 | 참조 입력과 특정 컷 편집이 이야기·정체성을 보존하는가? | 실제 모델 ID/revision, endpoint, 참조/편집 지원, 출력 조건, 가격, 계정/endpoint별 데이터 보관 조건 |
| ComfyUI 기반 로컬 경로 | 저장한 워크플로가 목표 PC에서 구도·정체성을 제어하고 재실행 가능한가? | 모델/가중치 출처·라이선스·checksum, 노드와 도구 버전, 의존성, 드라이버/메모리 요구, 원격 호출 노드 유무 |
| Krita / Krita AI Diffusion 후보 | 별도 텍스트 계층과 선택 영역 수정을 사람이 다루기 쉬운가? | 편집기와 플러그인 역할 구분, 로컬/원격 backend 설정, 호환성·라이선스·모델 요구, 내보내기와 편집 가능 계층 |

Gemini/OpenAI는 제공자 후보, ComfyUI는 workflow runtime 후보, Krita는 편집/검토 도구 후보다. 이들을 같은 종류의 모델이라고 취급하지 않는다. 로컬 비교 단위는 모델+workflow+도구+목표 PC의 정확한 구성이다. 로컬 UI를 써도 원격 backend/노드가 호출되면 외부 경로로 기록한다.

기존 D-0032 및 결정 팩의 구체 모델명은 제안 당시 후보 표기다. 이 계획은 그 이름의 현재 존재·지원·성능을 검증하거나 채택하지 않는다. 현재 모델 ID, 가격, 요구 사양은 `unknown`이다. 기능 목록만으로 승자를 고르지 않는다.

## 4. 같은 합성 입력으로 비교하는 절차

아래는 미래 시험 절차이며 지금 실행하지 않는다.

1. **승인·고정:** 합성 입력 패키지와 rubric을 사람이 검토하고 ID/버전/checksum으로 고정한다. 캐릭터의 고정 단서와 허용 변화, 이야기 비트·컷별 행동/표정/시점/구도/연속성, 별도 한국어 대사·화자·텍스트 안전 영역을 포함한다. 이야기 생성 후보를 별도로 시험하더라도 이미지 후보에는 동일하게 선택된 story/storyboard를 공급한다.
2. **조건 등록:** 같은 참조 파일/순서, 동일한 의미의 지시와 제외 조건, 화면비/목표 크기·crop·품질 목적, 첫 결과 수, 편집·재실행 수, 시간·비용 상한을 고정한다. 수치/차원은 미정이다. 미지원 조건은 차이를 명시하고 해당 차원의 직접 비교를 유보한다. 모델별 문법·전처리 변경은 별도 파생 prompt/workflow 버전과 차이표에 기록한다. 서로 다른 모델의 같은 seed는 동등 조건을 뜻하지 않는다.
3. **목표 PC preflight:** 선정된 PC에서 설치 요구·라이선스·저장 공간·원격 노드 여부를 확인한다. 설치도 별도 승인된 시험 범위에 포함되어야 한다. 시험 가능 여부가 미결이면 해당 후보는 `not_run`이며 성능 실패로 간주하지 않는다.
4. **외부 preflight:** 정확한 provider/model/endpoint/tier, 전송 목록, 자료 사용/보관/삭제/지역 조건과 전체 비용 추정·상한을 확인한다. 조건을 알 수 없거나 승인 범위를 벗어나면 호출하지 않는다.
5. **첫 결과 비교:** 같은 합성 입력으로 후보별 첫 결과와 모든 실패를 기록한다. 추천 최소 세트는 기준 뷰, 다른 각도/표정, 서로 다른 이야기 행동을 담은 소수 컷이다. 컷 수·출력 크기·조건당 시도 수는 사람이 확정할 시험 설정이며 실제 장면은 여기서 작성하지 않는다. 좋은 결과만 골라 비교하지 않는다.
6. **선택 컷 편집:** 같은 컷과 같은 수정 의도를 후보별로 시험한다. 수정할 단서/영역, 보존할 정체성/구도/텍스트, 범위 밖 변화와 사람 수정 시간을 기록한다. 편집 기능이 없으면 재생성 방식과 차이를 명시한다. 미선택 컷은 보존하고 전체 미리보기만 새 조합으로 만든다.
7. **재실행 확인:** 승인된 횟수 안에서 같은 입력·설정으로 재실행하고 차이를 기록한다. 목표 PC의 cold/warm 실행을 구분하고 준비 시간과 추론 시간을 분리한다. 외부 결과는 네트워크/queue 포함 지연임을 표시한다. 단일 표본을 신뢰 가능한 평균/실패율로 부르지 않는다.
8. **사람 선택:** 차원별 결과·필수 실패·운영 부담을 함께 검토한다. 후보 선택은 해당 구성과 시험 범위에 한정되며, 미선택/보류도 유효한 결과다. 채택 또는 새 모델로의 변경은 정확한 구성과 선택 근거를 기록한 후 별도 통합 범위를 검토한다.

## 5. 평가 rubric과 증거

차원별로 `목적에 맞음`, `사람 수정 후 사용 가능`, `필수 조건 실패`, `미시험/판단 보류` 중 하나와 구체 근거를 남긴다. AI evaluator는 컷/비트/입력 필드와 결과 위치를 인용하고 `blocker`, `revise`, `optional improvement`를 제안할 수 있다. 자동 단일 점수·feature list는 사람의 창작/권리/채택 결정을 대체하지 않는다.

| 차원 | 확인할 내용 | 남길 증거 |
|---|---|---|
| 캐릭터 정체성 | 실루엣·비율·팔레트·고정 단서가 각도/표정/행동이 바뀌어도 유지되는가? | 같은 입력 기준과 컷별 비교 위치, 허용 변화/정체성 drift 구분 |
| 스토리 충실도 | 컷의 행동·표정·인과·초점·설정/소품·연속성과 전체 비트 순서가 전달되는가? | 비트/컷 mapping, 누락·추가·반전된 의도, 전체 순서 미리보기 |
| 편집 가능성 | 특정 컷·영역만 고치며 나머지 단서·컷을 보존하는가? | 원본/변경본, 요청 범위/실제 변경 범위, 수동 수정 부담, undo/버전 관계 |
| 한국어 텍스트 분리 | 이미지에 대사가 굳어 있지 않고 별도 계층으로 원문/화자/읽기 순서가 유지되는가? | artwork 원본+별도 text/layout 버전+합성 preview, 한글 glyph·clipping·안전 영역 검사 |
| 재현성·출처 | 정확한 입력/모델/workflow/도구/설정을 복원하고 변경 이유를 설명할 수 있는가? | 버전/checksum, seed 지원/미지원, 재실행 차이, 숨은 defaults/제공자 미공개 필드 |
| 운영 조건 | 목표 PC 자원·설치 부담·지연·비용·전송/보관·라이선스가 허용되는가? | 장치 프로필, 개별 시도 시간/자원/실패, 비용/terms 검토 기록 |

한국어 대사는 이미지 생성에 맡기지 않는 비교 조건으로 둔다. 원문·화자·배치 anchor를 별도로 버전 관리하고 artwork 위에 검토용 overlay를 만든다. 텍스트만 수정할 때는 이미지 API/재생성을 호출하지 않는다. 의도하지 않은 문자/로고는 결함이다. 편집 가능한 레이어와 flattened preview를 구분하며, 좋은 한글 이미지 출력만으로 텍스트 편집 가능성을 통과시키지 않는다.

재현성은 (a) 설정/입력 복원 가능성, (b) 시각적 안정성, (c) byte 단위 일치 여부를 분리한다. seed/revision이 제공되지 않으면 `unknown` 또는 `unsupported`와 관찰 가능한 범위를 기록하며 동일 이미지 재생성을 보장하지 않는다. 원격 내부 설정을 추정해 채우지 않는다.

## 6. 반복·비용·중단 조건

D-0032의 **초기 컷당 러프 1개, 선택 컷 추가 후보 1개, 기술 retry 1회, 합성 비교 총 USD 5**는 추천이며 사람 확인 전의 실행 기본값이 아니다. 시험 sample/edit/repeat 수, timeout, 로컬 준비·실행 시간 한도, 요청당/전체 비용 상한과 실제 에피소드·월 한도는 미결이다. Story/board agent의 수정 한도를 image 호출 횟수로 자동 전용하지 않는다.

- 추정 비용에 모든 text/image 입력·출력, 참조, 편집, 재실행, retry, 실패 과금 가능성, 유료 도구가 있으면 그 비용을 포함한다. 모델·크기·품질·tier·통화·확인일을 기록한다.
- 매 요청 전 누적 사용액+미정산/진행 중 비용+다음 요청 최대 추정이 승인 상한 안인지 확인한다. 가격/과금 조건을 알 수 없으면 중단한다. 첫 시도 실패를 무료라고 가정하지 않는다.
- 자동 전체 에피소드 재생성을 금지한다. 사람 선택 컷과 승인된 범위만 새 run/version으로 만들고, 나머지 출력 ID를 보존한다. 영향받는 다른 컷은 근거와 추가 범위 승인 없이는 생성하지 않는다.
- 제한 초과, 반복 실패, 정체성/권리 문제, 평가 충돌, 개선 정체는 사람 검토로 종료한다. 기술 retry는 원인과 입력 변경 유무를 기록한다. 제한에 도달했다고 품질 통과/승인으로 처리하지 않는다.

## 7. 자료 전송·보관·복구 조건

- 앱, canonical 프로젝트 기록과 원본 자료는 로컬에 둔다. 외부에는 해당 작업에 필요한 합성 명세와 명시적으로 선택된 참조/수정 입력만 보낸다. 전체 채팅·DB·미선택 레퍼런스·비밀·키는 보내지 않는다. 자격 증명은 호출 인증에만 사용하며 prompt, 첨부, 로그, Git에 넣지 않는다.
- 유료 tier 사용 및 학습/제품 개선에 입력을 사용하지 않는 조건은 D-0032 추천으로 검토한다. 유료라는 이유만으로 이를 보장하지 않는다. endpoint/tier/계정별 입력·출력 저장, abuse log, retention 기간, 삭제 가능성/예외, 처리 지역/하위처리자, 선택 가능한 controls와 적용 가능성을 확인한다.
- 실제 전송 artifact ID/버전, provider, endpoint, 검토한 약관 URL/확인일, 사람의 허용 범위, 잔여 위험을 남긴다. 미공개/불명확/허용 불가 조건이면 해당 후보를 중단한다. 학습 비사용과 무보관은 다른 조건이다.
- 로컬에서도 candidate별 임시 파일, 로그, 참조, 선택/거절/격리 출력과 manifest를 project/evaluation 경계로 분리한다. 보관 위치·기간·용량·백업/암호화·삭제 책임자는 미정으로 두고 실행 전에 확정한다. 실패/거절 이력은 정한 정책에 따라 추적하되 무기한 보관을 자동 결정하지 않는다. 미디어 삭제 시 manifest에 삭제 상태/이유와 출처 관계를 보존한다.
- 오류/권리/정체성 문제는 해당 출력을 격리하고 선택/후속 소비에서 제외한다. rollback은 이전 유효 버전을 가리키는 새 기록이며 원본을 덮어쓰거나 실패 이력을 지우지 않는다.
- 실제 자료 전송은 합성 시험과 별도 승인을 요구한다. 이 명세는 API 키 설정이나 제공자 연결을 요청하지 않는다.

## 8. 미래 결과 기록과 검증

평가 record의 최소 항목(명세 필드이며 기존 JSON Schema 확장 완료를 뜻하지 않음):

| 묶음 | 필수 기록 |
|---|---|
| 소유·버전 | evaluation/protocol ID와 버전, 합성 `project_id`/`content_id` 해당 범위, owner, 날짜, 정확한 input refs/checksums, rubric 버전 |
| 구성 | candidate ID, provider/model/revision 또는 checksum, workflow/prompt/tool/plugin 버전, target PC profile, parameters/defaults/seed 지원 상태 |
| 시도 | attempt/run ID, 목적·선택 unit IDs, 시간/비용/실패, 요청·응답 식별자, 출력 refs/checksums, `retry_of`/`supersedes`, 변경 범위 |
| 검토 | 컷별/전체 preview refs, 차원별 관찰과 미시험 항목, 전송/보관/라이선스 증거, 사람 피드백·선택 이유·유효 범위·남은 위험 |
| 인계 | `not_run`/부분 결과/선택/거절/보류 구분, 승인 기록과 별도 실행 권한, Stage 05 next consumer, 후속 검증 요구 |

미래 시험 종료 전 검증: 모든 후보가 같은 source snapshot/rubric을 받았는지, 변환/미지원 차이가 공개됐는지, 첫 결과·실패가 누락되지 않았는지, 미선택 컷과 이전 버전이 보존됐는지, 별도 한글 text/layout과 전체 preview가 검토됐는지, 비용·전송·보관 증거가 있는지, `unknown`을 추정으로 채우지 않았는지 확인한다. 구조 검증은 창작 품질·권리·G3 승인이 아니다.

현재 문서 검증은 링크/용어/권한/추천 상태/두 문서 간 계약 일치 검토로 한정한다. 시험·이미지·속도·비용·재현성 실측 결과는 아직 없다. 사람 미선택이면 Stage 05 후보는 미선택으로 유지한다.

## 9. 남은 선택과 충돌 확인

- 목표 PC 프로필과 로컬 모델/workflow/노드 구성.
- 외부 모델 ID/revision, endpoint/tier, 허용 payload와 자료 보관 조건.
- 합성 최소 세트/표본 수, 해상도·품질·crop, 비교 불가 조건 처리, 편집·재실행 횟수.
- 필수 평가 조건과 허용 수동 수정 부담, 시간·비용 한도.
- 로컬/원격 보관·삭제·백업·PC 이동 정책과 책임자.
- D-0032의 수치·유료 tier 추천 채택 여부와 별도 시험 실행 승인.

기존 결정 팩/제품 방향 문서의 구체 모델명이나 수치가 확정값처럼 보이면 메인 통합 검토에서 추천/미결 상태로 일치시킨다. 이 작업은 D-0031–D-0033을 변경하거나 새 채택 결정을 만들지 않는다. 기존 mock/schema는 기술 흐름의 증거일 뿐, 본 평가 확장 필드와 창작 품질이 검증됐다는 근거가 아니다. 이번 위임에서는 두 허용 문서만 수정하며 Git add/commit/push는 하지 않는다. 메인 스레드가 검토 후 작업별 통합을 담당한다.
