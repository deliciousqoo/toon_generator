# 캐릭터 후보와 시트

기준일: 2026-10-18. D-0038의 기본 이미지 연결은 **Codex 이미지 생성 + 앱 반영**이다. 앱의 ChatGPT 구독 연결은 방향 대화에 사용한다. 이미지 생성 요청은 앱에서 준비하고 이 Codex 대화에서 실행한 뒤 결과를 가져온다. 유료 API나 자동 이미지 생성기로 전환하지 않는다.

## 한 번의 작업 흐름

1. 캐릭터 방향의 정확한 버전을 확인한다.
2. 후보 요청을 만든다. 요청에는 확인한 방향과 원하는 차이, 수정 시 유지할 특징이 포함된다.
3. 요청문을 Codex에 전달해 이미지를 생성하고 해당 요청에 **이미지 가져오기**로 등록한다. 수정 요청에 기준 이미지가 있으면 그 이미지도 함께 전달한다.
4. 후보를 비교한다. 바꾸고 싶은 점을 입력해 수정 요청을 만들고, 수정본을 같은 요청에 등록한다. 이전 이미지와 수정 이유는 남는다.
5. 사용할 후보의 정확한 버전을 선택한다.
6. 시트에 필요한 모습·표정·포즈를 고르고 구성을 저장한다. 처음 제시되는 항목은 제안이며 저장한 선택이 이번 시트의 기준이 된다.
7. 항목별 생성 요청을 실행하고 이미지를 등록한다. 선택한 후보가 항목에 맞으면 그 이미지를 그대로 사용할 수 있다.
8. 구성한 시트를 미리 보고 필요한 항목만 수정한다. 각 수정은 이전 시트를 보존하며 새 버전으로 이어진다.
9. 모든 항목을 살펴보고 현재 방향·후보·시트의 정확한 묶음을 최종 확인한다. 이후에도 수정 단계로 돌아갈 수 있다.

최종 확인 화면의 **시트 내려받기**는 현재 승인된 시트의 이미지, 캐릭터 방향·선택·구성·생성 출처 JSON과 체크섬을 ZIP으로 묶는다. 사용한 수정 원본도 추적할 수 있게 포함하며 선택하지 않은 별도 후보는 넣지 않는다. 이 ZIP은 시트 패키지이며 대화·체크포인트를 복원하는 전체 프로젝트 백업은 아니다.

## 수정과 복구

- 방향을 다시 열면 그 방향에 의존하던 선택과 현재 시트 확인이 해제된다. 이전 후보·이미지·시트·결정 기록은 남는다.
- 다른 후보를 선택하거나 시트 구성을 바꾸거나 한 항목을 수정하면 이전 최종 확인을 다시 요구한다.
- 앱을 재시작해도 생성 요청, 등록한 이미지, 선택과 버전은 보존된다. 대기 중인 이미지 요청을 자동 실행하거나 재전송하지 않는다.
- 이미지 파일이 사라지거나 체크섬이 달라지면 해당 결과의 최종 확인과 후속 인계를 차단한다. 현재 방향의 후보는 선택하지 않은 이전 후보까지 무결성을 확인하므로, 하나가 손상되어도 프로젝트 불러오기가 멈출 수 있다. 안내된 원본 파일을 복구해야 하며 복구 전용 UI는 아직 없다.
- 생성 출처의 모델·시드·실행 프롬프트를 모르면 알 수 없는 값으로 남긴다. 앱이 추천한 요청문을 실제 실행 프롬프트로 간주하지 않는다.

이 흐름의 완료는 선택한 구성의 캐릭터 시트에 대한 확인이다. 작품 제작·게시나 권리 검수를 자동 승인하는 동작은 아니다. 최초 화면 검증은 기존 가상 캐릭터로 수행한다. 이미지 원본과 실제 프로젝트 데이터는 Git에 넣지 않는다.

최종 확인 뒤 **이야기·콘티**에서 에피소드를 시작할 수 있다. D-0039의 [이야기·콘티 흐름](character-episode-guide.md)은 이 정확한 캐릭터 묶음을 고정해서 모든 역할에 전달한다. 이전 `?storyFixture=1` 기술 경로는 계속 합성 자료만 사용한다.
